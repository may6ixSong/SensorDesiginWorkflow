# 03. 캔버스

## 1. 버전 개념의 제거

**캔버스에는 version이 없다.** 이번 개정에서 가장 큰 구조 변화다.

- 모든 캔버스 편집은 **overwrite**다. 저장하면 그게 곧 현재 상태다.
- 스냅샷을 찍지 않는다. 과거 캔버스로 되돌아가는 기능도 없다.
- 따라서 **Edit 권한자와 View 권한자가 완전히 동일한 캔버스를 본다.** 예전처럼 View 권한자에게만
  "마지막 release 시점"을 보여주는 분기는 폐기한다.
- release 이력에서 재현해야 할 것은 **표(table) 형태의 산출물 목록**이지 캔버스가 아니다(05장).

## 2. 블록 표시

### 2.1 블록에 버전을 쓰지 않는다

블록에는 버전 라벨(`v1.2` 등)을 **표시하지 않는다.** 버전은 상세 slide를 열어야 보인다.

### 2.2 publish 상태 배지

대신 블록마다 아래 3상태 중 하나를 배지로 표시한다. 숫자는 쓰지 않는다.

| 상태 | 판정 | 표시 |
|---|---|---|
| **미발행** | published 버전이 하나도 없다 | 회색 · 점선 테두리 |
| **발행됨** | published 버전이 있고, 마지막 release 이후 major 변화가 없다 | 기본색 · 실선 |
| **신규 발행** | published 버전이 있고, 마지막 release 이후 **major가 올라갔다** | 강조색 · 채워진 점 |

- "신규 발행"은 곧 **다음 release에서 highlight될 대상**이다(05장 §3). 캔버스에서 미리 눈에 띈다.
- 열람 권한이 없는 산출물의 배지는 그리지 않는다 — 상태 자체가 정보이므로 노출하지 않는다.

### 2.3 미매핑 블록

`artifactId === null` 인 블록은 정상 상태다(자리는 잡아두고 출처는 나중에 지정).
- 별도 아이콘으로 구분한다.
- **release 대상에서 제외**된다.
- recipient 설정 UI를 표시하지 않는다.

## 3. 편집 세션 lock

캔버스 편집은 **단독 점유**다. 동시 편집으로 인한 덮어쓰기를 구조적으로 차단한다.

### 3.1 규칙

| 항목 | 값 |
|---|---|
| TTL | **10분** |
| 갱신 | 편집 중이면 자동 갱신(하트비트). 갱신마다 `expiresAt` 이 다시 10분 뒤로 밀린다 |
| 하트비트 주기 | 2분 (TTL의 1/5 — 네트워크가 몇 번 실패해도 만료되지 않는다) |
| 만료 후 | **다른 Edit 권한자가 자유롭게 점유**할 수 있다 |
| 강제 해제 | **Admin만** 가능 |
| 정상 종료 | 저장 · 취소 · 페이지 이탈 시 lock 해제 |
| 비정상 종료 | 브라우저를 그냥 닫으면 TTL 만료로 자연 해제 |

### 3.2 점유 중 화면

- 다른 사용자에게는 편집 진입 버튼이 비활성화되고, **"○○○님이 편집 중 (남은 시간 m:ss)"** 을 표시한다.
- 남은 시간은 클라이언트가 `expiresAt` 으로 계산해 카운트다운한다.
- 만료되면 버튼이 자동으로 활성화된다(새로고침 불필요).
- Admin에게만 **"강제 해제"** 버튼이 함께 보인다. 누르면 confirm 후 해제한다.

### 3.3 lock을 쓰지 않는 것

**Schedule(phase 편집)과 Edit Information(workflow 설정)은 lock 대상이 아니다.**
항상 latest overwrite로 저장한다 — 충돌 가능성이 낮고, 충돌해도 손실이 작기 때문이다.

## 4. 편집 모드

### 4.1 진입 조건

- Edit 권한자(Owner · Edit Access · Admin)
- lock을 점유할 수 있어야 한다(§3)

### 4.2 배경 전환

편집 중임이 한눈에 들어오도록 캔버스 배경을 바꾼다. **light/dark 양쪽 모두** 정의한다.

| 테마 | 조회 모드 | 편집 모드 |
|---|---|---|
| light | 기본 배경 | 따뜻한 크림 톤 + 미세 그리드 (예: `#FFFBF2`, grid `#EFE4CE`) |
| dark | 기본 배경 | 짙은 남색 톤 + 미세 그리드 (예: `#0E1524`, grid `#1B2740`) |

- 정확한 값은 `web/src/theme/theme.ts` 의 토큰으로 정의하고, 캔버스는 토큰만 참조한다.
- 배경 전환 자체도 애니메이션한다(06장의 `motion.surface`).
- 캔버스 상단에 얇은 **"편집 중" 바**를 띄우고, 그 안에 저장 / 변경 취소 버튼과 lock 잔여 시간을 둔다.

### 4.3 편집 중 비활성화

**app bar를 제외한, 캔버스 밖의 모든 액션 버튼을 비활성화한다.**

| 영역 | 편집 중 |
|---|---|
| app bar (Project/Workflow select, 언어, 테마, 프로필, 알림) | **활성** |
| Workflow information 수정 | 비활성 |
| Schedule / Edit phases | 비활성 |
| Permissions | 비활성 |
| **Release** | 비활성 |
| Release history | 비활성 |
| 앞으로 추가될 모든 액션 버튼 | **비활성** |
| 캔버스 zoom / pan | 활성 |
| 수신 부서 필터 | 활성 |
| 블록 상세 slide 열기 | **비활성** (편집과 충돌) |

> 구현 지침 — 개별 버튼마다 `disabled` 를 흩뿌리지 않는다. 캔버스 밖 액션 영역을 감싸는
> **단일 컨텍스트**(`<CanvasEditingGate>`)를 두고, 편집 중이면 그 아래 모든 액션을 일괄 비활성화한다.
> 그래야 나중에 버튼을 추가해도 자동으로 규칙이 적용된다.

### 4.4 저장 / 취소

둘 다 **confirm 후** 실행한다.

| 동작 | confirm 문구 (ko / en) |
|---|---|
| 저장 | "변경한 내용을 저장하시겠습니까?" / "Save your changes?" |
| 변경 취소 | "변경한 내용을 모두 취소하시겠습니까? 되돌릴 수 없습니다." / "Discard all changes? This cannot be undone." |

- 변경 사항이 하나도 없으면 confirm 없이 그냥 편집 모드를 빠져나온다.
- 저장 성공 시 lock을 해제하고 조회 모드로 전환한다.

## 5. 블록과 flow 편집

### 5.1 블록 배치

기존과 동일하다.
- 드래그로 자유 배치. 다른 블록을 밀어내지 않고, 겹침을 허용한다.
- 드래그 종료 위치의 x 좌표가 속한 phase 레인으로 `phaseId` 가 자동 갱신된다.
- phase 경계를 넘을 때는 누적 모멘텀이 필요하다(살짝 걸치면 되돌아온다).
- phase 레인 폭은 편집 모드에서 드래그로 조절한다.

### 5.2 새 Artifact 추가

- **버튼 1개로 통합한다.** "주는 산출물 / 받는 산출물" 구분 버튼을 없앤다.
- 클릭하면 **내가 주는 산출물** 기준으로만 생성된다(`intent: 'own'`).
- `intent` 필드 자체는 스키마에 남겨둔다 — TODO T2에서 되살린다.
- **받는 산출물의 선택 가능 범위 정책은 이미 확정되어 있다.** 04장 §6 참조.
  UI만 나중에 만든다.

### 5.3 Flow 편집

| 동작 | 조회 모드 | 편집 모드 |
|---|---|---|
| 블록 클릭 | 연결된 흐름 highlight (prev는 prev만, next는 next만 추적) | 블록 선택/이동 |
| **flow 클릭** | 해당 flow만 강조 | **그 flow와 연결된 블록 양끝을 highlight** → confirm 후 삭제 |
| 블록 상세 열기 | highlight 상태에서 뜨는 "상세" 버튼 | 열 수 없음(§4.3) |

flow 삭제 confirm 문구:
> "이 연결을 삭제하시겠습니까?" / "Delete this connection?"
> 본문에 연결의 양끝 산출물 이름을 함께 보여준다 — `A → B`.

- 라우팅은 직교(수직/수평)만 쓰고 곡선을 쓰지 않는다.
- 양방향 연결은 양쪽 화살촉 + 선 중앙 순환 아이콘으로 표현하며, 편집 모드에서는 아이콘을 숨긴다.

## 6. 필터

### 6.1 수신 부서 필터

캔버스 상단에 **수신 부서 필터**를 둔다.

- 선택한 부서가 recipient에 포함된 산출물만 강조하고, 나머지는 흐리게(dim) 처리한다.
  숨기지 않는 이유는 flow 구조가 끊겨 보이면 안 되기 때문이다.
- 다중 선택 가능하며, 선택 해제하면 전체로 돌아온다.
- 후보는 그 과제에 등록된 부서(`Project.departments`).
- **recipient 판정**은 tier에 따라 다르다(04장 §3):
  - A → **그 block**의 `recipients.editAccess.departments` + `recipients.viewAccess.departments`
    (workflow마다 다를 수 있다 — artifact가 아니라 block에 저장된 값)
  - B/C/D → **그 artifact**의 `viewAccess.departments` (모든 workflow에서 동일)
- 편집 모드에서도 필터는 쓸 수 있다(§4.3).

### 6.2 만들지 않는 필터

**tier 필터는 만들지 않는다.** 요구되지 않았고, 화면만 복잡해진다.
